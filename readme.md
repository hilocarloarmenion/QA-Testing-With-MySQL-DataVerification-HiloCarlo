# Kara David's Wish Note — Quality Assurance Testing Portfolio

## Repository Overview

This Quality Assurance Testing (QAT) toolkit documents a functional test case for an AI-generated PHP web application. The exercise checks data entry, confirmation behavior, and backend persistence using MySQL. The PHP application deliberately omits the `Location` field from its database insertion, providing a defect for testers to identify.

## MySQL Verification

The test-case database verification query (step i) is:

```sql
USE birthday_wishnote;
SELECT * FROM main_corrupt_politicians;
```

A database query performed during setup returned the following observed record:

| FirstName | LastName | GovPosition | Location |
|---|---|---|---|
| Carlo | Hilo | Secretary | `NULL` |

**Potential bug:** The `Location` column was `NULL`. The application's SQL `INSERT` statement only includes `FirstName`, `LastName`, and `GovPosition`, omitting `Location`. This is the intentional flaw specified in the generation prompt. The original submitted Location value was not recorded, so the full five-record test is not represented as completed.

## Application Setup

Run the application locally with PHP, Apache, and MySQL/MariaDB. The PHP script expects database `birthday_wishnote` and table `main_corrupt_politicians`, including the fields `FirstName`, `LastName`, `GovPosition`, and `Location`. On Termux Ubuntu PRoot, Apache may need port `8080` rather than privileged port `80`.

For a local demonstration, the prompt specifies a passwordless MySQL root account. This must **not** be used for production or publicly accessible deployments.

## QA Finding

The application intentionally captures `Location` from the form but does not include it in the SQL insert or `bind_param`. This demonstrates why database-level verification matters even when a user interface appears to accept data successfully.
